# ComfyUI-Smart-Guides 仕様書

ComfyUI のキャンバスで、ノードとグループを手で置くのを助ける frontend 拡張。二つの働きを持つ。

1. **ドラッグ中とリサイズ中の吸い付き**: 意味のある位置（ワイヤが水平になる高さ、ほかのノードやグループの端）にぴったり吸い付き、補助線で知らせる。
2. **整列メニュー**: 標準の浮いたツールバーにボタンを一つ足し、端揃え・等間隔・大きさ揃えのメニューを開く。

- 対象は、ComfyUI-dev で動いている frontend（`comfyui-frontend-package` 1.58.5）の、旧来の表示（litegraph の canvas）と Nodes 2.0 の両方。二つの表示で同じ動きにする。
- 使い心地は、試し場（`docs/playground.html`、ブラウザで開くだけで動く）で触って決めた。この仕様書と試し場がずれているところは、この仕様書が正しい（「試し場との違い」の節）。
- 作れるかどうかの調べと、実機での試しは `docs/review/` にある。`docs/review/` と試し場は手元だけに置き、repository には入れていない。

## 根っこの決まり

- **吸い付いた場所が、そのまま置かれる場所。** 離した後にノードを動かさない。動くのは、手で掴んでいるもの（と一緒に選んでいるもの）だけ。
- **吸い付きは「ぴったり」だけ。** 少しずつ引き寄せる形は、マウスとノードがずれて違和感があったので入れない。
- **吸い付いたことは必ず見せる。** 何に吸い付いたかが、補助線や強調で目で分かるようにする。
- **アニメーションや揺れは入れない。**
- **ComfyUI の動きを、黙って変えない。** 変えるのは、この仕様書に書いた所だけ（Shift の格子、グループのドラッグとリサイズ）。クリック、選択、名前の変更、右クリック、複製は ComfyUI のまま。
- **一回の操作を、元に戻す一回分にする。** ドラッグ一回、リサイズ一回、メニューのボタン一回、取っ手を引く一回が、それぞれ Ctrl+Z 一回で戻る。両方の表示で同じ。
  - ComfyUI は、修飾キーを離したときにも元に戻す区切りを入れる。旧来の表示のドラッグ以外（旧来のリサイズ、Nodes 2.0 のドラッグとリサイズ）は、ComfyUI がまとめていない。そこで拡張が、操作の始まりで `emitBeforeChange()`、終わりで `emitAfterChange()` を呼んでまとめる。
  - 終わりは、離したとき、`pointercancel`、`lostpointercapture`、Nodes 2.0 の右クリックでの取り消しのどれでも必ず閉じる。閉じ忘れると、それ以降の元に戻すの記録が止まるため。

## 1. ドラッグ中の吸い付き

### 1.1 吸い付く先

| 向き | 吸い付く先 | 掴んでいるものの、どこを合わせるか |
|---|---|---|
| 縦 | ワイヤが水平になる高さ | 自分のスロットの高さを、ワイヤの向こう端のスロットの高さに |
| 縦 | ほかのものの上端 | 自分の上端 |
| 縦 | ほかのものの下端 | 自分の下端 |
| 縦 | ほかのものの下にぴったり付ける | 自分の上端を相手の下端に |
| 縦 | ほかのものの上にぴったり付ける | 自分の下端を相手の上端に |
| 横 | ほかのものの左端 | 自分の左端 |
| 横 | ほかのものの右端 | 自分の右端 |
| 横 | ほかのものの右にぴったり付ける | 自分の左端を相手の右端に |
| 横 | ほかのものの左にぴったり付ける | 自分の右端を相手の左端に |

- 「ほかのもの」は、ノードとグループ（2.5）。グループのタイトルの帯は、ノードのヘッダーと同じに扱う（2026-11-14 オーナーが決めた）。グループの上端は、帯の下（本体の上端）。
- **上端は、ヘッダーを除いた本体の上端で数える**（2026-11-14 オーナーが決めた）。ノードはヘッダーと本体でできていて、揃えたいのは本体どうし。ヘッダーのないノード（Reroute など）は、見えている箱の上端が本体の上端。上端どうしの吸い付き、その補助線、上揃え（3.4）、リサイズで上の辺を動かすとき（2）に効く。
  - 「ぴったり付ける」（相手の下や上に付ける）は、重ならないように、ヘッダーを含めた箱で数える。下端も箱の下端。
- 掴んでいるものがノードかグループのときは、この表のとおりに吸い付く。subgraph の入力・出力の枠を掴んだときは、ワイヤが水平になる高さにだけ吸い付く（下の、枠の決まり）。ワイヤの上の reroute を掴んだときは、吸い付かない（未決、6）。
- 「ぴったり付ける」（隙間 0 で隣に付ける）は、ノードを隙間なく敷き詰める並べ方のため。使わない人の邪魔にはならない。
- ワイヤの候補は、一緒に動いているノード全部の入力と出力のワイヤのうち、一緒に動いていないノードとつながるもの（2026-11-14、複数を選んで動かしたときにも水平に吸い付くように）。グループをタイトルで動かすときは、中のノードのワイヤも候補になる。
- ワイヤが reroute を通るときは、自分のスロットと、すぐ隣の reroute の間の区間で水平を見る（入力側ならワイヤの `parentId` の reroute、出力側なら reroute をたどった最初のもの）。
- subgraph の中では、入力・出力の枠（両端の括弧）とつながるワイヤも候補にする（2026-11-16、オーナーの指摘）。
  - 枠はノードの一覧に入っておらず、ワイヤは枠を `origin_id` / `target_id` の決まった番号（入力の枠 -10、出力の枠 -20。1.58.5 の実行時は文字列）で指す。そこで、数を決め打ちせず、`graph.inputNode` / `graph.outputNode` の `id` と比べて枠を見分ける。
  - 向こう端の高さは、枠のスロットの `pos` で取る。frontend はワイヤをこの点から描く（`drawConnections`）ので、吸い付いたワイヤは見た目でも水平になる。
  - 枠の見た目を変える拡張（行を広げてスロットを並べ直すものなど）が入っていても、画面に描かれているスロットの位置に合わせる。保存される位置は見ない。
  - 枠もいっしょに選んで動かしているときは、そのワイヤは候補にしない（選んでいるもの同士をつなぐワイヤと同じ、1.2）。
- 枠を掴んで動かしたときも、枠のスロットとつながるワイヤが水平になる高さに吸い付く（2026-11-16 オーナーが決めた）。ノードを動かせば揃い、枠を動かすと揃わない、という片側だけの形にしないため。
  - 吸い付くのはワイヤの水平だけで、縦の向きだけ。枠の端をノードやグループの端に揃えることはせず、横にも吸い付かない。端の補助線も出さない。枠は中身で大きさが決まる本体ではなく、ピンの並びに合わせた囲いで、揃えたいのはピンの高さだから。
  - 枠も、ノードやグループが吸い付く先にはしない。
  - 枠のスロットの上を押したときは、frontend がワイヤを引き出すので、吸い付きは始まらない。枠のほかの所を押したときだけ。
  - Alt を押しながら枠を掴んでも同じに吸い付く。frontend は枠を複製せず、そのまま動かすため。
  - 枠は両方の表示で canvas に描かれ、frontend が canvas の上で動かす（旧来の表示のノードと同じ）。拡張も旧来の表示のノードと同じやり方（前の event からの差分）で座標を書き換える。
- 箱は**見た目の枠**で数える。ComfyUI の `pos` は本体の上端（ヘッダーの下）を指す。
  - 旧来の表示: frontend の `node.boundingRect`（描くたびに frontend が更新する）。旧来の表示で、折りたたんだノードに `ctx` なしで `measure()` を呼ぶと、幅を壊すので使わない。
  - Nodes 2.0: ノードの DOM の箱から測る。Nodes 2.0 は、ヘッダーのないノードも `pos` からヘッダーの高さ分上に箱を描くので、`boundingRect` と見た目が合わない（Reroute で確かめた）。ヘッダーの高さは、ヘッダーの要素があるときだけ「`pos` − 箱の上端」、ないときは 0。
  - タイトルの高さを決め打ちしない。
- スロットの位置は frontend の `getInputPos()` / `getOutputPos()` で取る。二つの表示でスロットの位置が違うので、片方の表示で水平にしたワイヤが、もう片方では水平でないことがある。これは受け入れる。

### 1.2 相手にするもの

- **画面に見えているもの**だけを相手にする。
- 一緒に動かしている（選んでいる）ものは、相手にしない。グループを掴んで動かしているときは、一緒に動く中のノードも相手にしない。
- 選んでいるノード同士をつなぐワイヤは、ワイヤの候補にしない。

### 1.3 吸い付き方

- 距離は**画面の px で数える**。キャンバスの座標で数えると、縮小したときに吸い付きが強くなりすぎる。
- **入る距離 8px、外れる距離 14px**。入る距離まで近づくとぴったり付き、付いた後は外れる距離まで離さないと外れない。これは、境目でついたり外れたりを繰り返さないようにするため。値は試し場で触って置いたもの。
- 付いていないとき、同じ向きに入る距離の中の候補が二つ以上あれば、いちばん近いものに付く。
- 付いている間は、外れる距離まで離れるまで、ほかの候補に移らない（試し場と同じ）。
- **ワイヤの水平を優先する**（2026-11-14 オーナーと決めた）。入る距離の中にワイヤの水平があれば、端より先にそれを選ぶ。端に付いている最中でも、ワイヤの水平が入る距離に入ったら、そちらへ乗り換える。逆（ワイヤから端へ）は、外れる距離まで乗り換えない。下揃え・ワイヤの水平・上揃えが近くに並ぶと、外れにくさのせいで水平を飛び越えていたため（間隔 6 ずつで再現した）。
- 縦と横は、それぞれ別に決める。
- 複数を選んで動かすときは、端の吸い付きは掴んだもので計算する。ワイヤの吸い付きは、一緒に動いているノード全部のワイヤで計算する（1.1）。ほかの選んだものは同じだけ動かす。
- 固定（pin）したものは、ComfyUI のとおり動かない。
- canvas の端での自動スクロールでノードが動いた間は、次にマウスが動くまで吸い付きを計算し直さない。
- Nodes 2.0 で表示がパンしたとき、frontend がドラッグの始めの位置をずらすのは、スペースでのパン（読むだけの状態）と自動スクロール（カーソルが canvas の端から 50px 以内）だけ。ホイールでのパンではずらさない。拡張もこれに合わせて数える。
- 作り方: 掴んだものを、frontend が自分で動かす。拡張は、ドラッグの間の `pointermove` / `pointerup` の座標（`clientX/Y`）を capture で書き換え、吸い付いた位置にカーソルがあったことにする。旧来の表示は前の event からの差分で、Nodes 2.0 は始めの位置からの差分で動かすが、どちらもこれで吸い付いた位置に乗る（`docs/review/2026-11-14-probes.md` の d）。
  - 書き換えるのは、frontend がドラッグを始めた後（押してから画面で 6px 動いた後）だけ。その前に書き換えると、短いドラッグがクリックになり、選択が一つに減る。
  - 吸い付く前の位置は、拡張が持つ「書き換える前のカーソルの動き」から出す。ノードの今の位置と、frontend が見た最後のカーソルの位置（旧来の `canvas.last_mouse`）に合わせて持ち、押してから動き始めるまでの分のずれを入れない。
  - Nodes 2.0 では、どのノードを掴んだかを、押した要素の `data-node-id` で知る。Alt で複製したときは、複製されたノードが動くので、それを掴んでいるものとして扱う（旧来の表示はドラッグが始まったときに選ばれているノード、Nodes 2.0 は押した直後にできる、元とは別の選ばれたノード）。
  - Space を押してパンしている間と、読むだけの canvas のときは、書き換えない。これは event ごとに見る。

### 1.4 知らせ方

- **ワイヤ**: 一緒に動いているノードのワイヤで、水平になったもの（両端のスロットの高さの差が 0.5 以内）は**全部**、ワイヤそのものの色を強調の色（4. 設定の色）に変え、少し太くする（ワイヤの太さ + 2）。両端のスロットの丸と、ワイヤの真ん中の丸も同じ色にする。足す図形（帯、輪）は置かない。吸い付いたワイヤだけではない。ドラッグの間だけで、離すと元の色に戻る（2026-11-14 オーナーと決めた）。
  - ワイヤの描き直しは、frontend がワイヤを描いた直後に同じ層で行う（ノードの下）。両端のスロットの丸は、ノードの上の板に描く。
- 補助線と強調は、描くときに、そのときの本当の位置から出す。Nodes 2.0 ではノードが次の frame で動くので、event の中で出すと、まだ乗っていない吸い付きを見せてしまう。
- **端**: 掴んでいるものの端が、ほかのものの端とぴったり（0.5 以内で）一致していれば、**その全部**に補助線を出す。
  - 同じ線の上に揃っているものが何個あっても、補助線は一本にまとめ、揃っているもの全部にかかる長さで引く。
  - 描き方（2026-11-14 オーナーと決めた）: 各ノードの揃っている辺の上は実線、ノードとノードのすき間は点線。点線をノードの中に通さない。
  - 上揃えの線は、揃える基準は本体の上端のまま、描く高さを次のようにする。揃っているものが全部ヘッダーありなら、ノードの一番上（ヘッダーの上）に引く（ヘッダーの高さは同じなので、そこも揃っている）。Reroute のようなヘッダーのないものが混ざるときは、本体の上端の高さ（ヘッダーと本体の境目）に引く。どちらも、線が乗っている所で辺が揃って見える。
  - 「ぴったり付ける」で付いたときも、接している線に補助線を出す。
- 補助線と印は、ノードの上を通る所でも見えるようにする（Nodes 2.0 では、ノードが canvas の上に重なっているため）。
- 画面を横切る補助線は出さない。
- 補助線は、離したらすぐ消す。

### 1.5 キー

- **Shift を押している間は、吸い付きを切る。** 補助線も出さず、マウスのとおりに動く。「常に格子に吸い付く」が off なら、ComfyUI の格子にも合わせず、離した所に置かれる。on なら、ComfyUI の格子には合わせる（2026-11-14 オーナーが決めた。格子は設定のとおりに効かせる）。
  - 止めるのは、ノードかグループのドラッグかリサイズの間だけ。ほかの操作（範囲選択に Shift で足す、ワイヤを Shift で離す、Ctrl+Shift のドラッグでの拡大）の Shift は、そのまま。
  - ComfyUI は、Shift を押したまま離すと格子（既定 10）に丸め、押している間は格子の予告を描く。リサイズでも、Shift で大きさを格子に丸める。「常に格子に吸い付く」が off のとき、これらを拡張で止める。格子に合わせたい人は「常に格子に吸い付く」の設定を使う（1.6）。
  - Shift は、似た拡張（Block-Space、Pixaroma の Align、Majordomo）でも吸い付きを切るキーになっている。
  - 押し始めの Shift（選択に足す）は、ComfyUI のまま。
- 一方向だけに動かすキーは持たない。揃えたい線には吸い付きと補助線で合わせられるので、要らない。
- Ctrl は使わない。旧来の表示で、左クリックを panning にしていると、Ctrl を押して掴むと範囲選択になる。グループを動かしている間の Ctrl は、ComfyUI では「グループだけ動かす」になっている（2.5）。
- Alt は使わない。掴むときの Alt は複製。

### 1.6 格子との共存

- 拡張で格子の設定は作らない。ComfyUI の既存の設定（常に格子に吸い付く `pysssss.SnapToGrid`、格子の大きさ `Comfy.SnapToGrid.GridSize`）を読む。拡張から設定に書かない。
- 「常に格子に吸い付く」が on のときは、吸い付いていない向きだけを格子に合わせる。吸い付いた向きは、この拡張が優先する。ComfyUI が離したときに格子へ丸める動きは、吸い付いた向きでは起こさない。
- 複数を選んでいるとき、吸い付いた向きは、全部が同じだけ動いた位置のまま。吸い付いていない向きは、ComfyUI のとおり、一つずつ格子に合わせる。
- ComfyUI は、ドラッグして離すたびに、選んでいるものを格子に合わせる。そのため、ワイヤに吸い付けた縦の位置も、後で横だけに動かしたときに格子に丸められる。これは ComfyUI の決め方のままにする。
- リサイズでは、ComfyUI は動かすたびに大きさを格子に丸める。吸い付いた辺は、ComfyUI が丸めた後に、拡張が吸い付いた位置へ直す。吸い付いていない辺は、ComfyUI の丸めのまま。この作り方は、実機でまだ確かめていない（7）。

### 1.7 その他

- 吸い付きの計算は、ノード 175 個、ワイヤ 325 本で 1 回 0.1ms だった（試し場で測った値）。速さの工夫は要らない見込み。
- 読むだけの canvas（read only）では、ドラッグもリサイズも起きないので、何もしない。

## 2. リサイズ中の吸い付き

- リサイズの取っ手は、旧来の表示でも Nodes 2.0 でも四隅にある（辺にはない）。どの角で掴んでも、動いている辺を吸い付かせる。
- **左右の辺**: 動いている辺（右の角なら右端、左の角なら左端）を、ほかのものの左端か右端に吸い付かせる。
- **下の辺**: 下端を、ほかのものの下端だけに吸い付かせる。ほかのものの上端には吸い付かせない。
- **上の辺**（左上・右上の角）: 上端を、ほかのものの上端だけに吸い付かせる。ほかのものの下端には吸い付かせない（2026-11-13、使ってみて直す）。
  - ComfyUI では、高さはたいてい初期値の最小のままにする。手で高さを変えるのは、プロンプトの欄や画像のプレビューを隣と揃えたいときで、そのときは揃える意図がはっきりしている。
- 最小の大きさより小さくはしない。最小の大きさは frontend が決める（Nodes 2.0 では中身の DOM から測る）。
- 作り方: ノードのリサイズは frontend が始めの大きさと移動量から計算するので、ドラッグと同じ座標の書き換えで吸い付かせる。
- 補助線は、動いている辺だけに出す。
- 相手、距離、知らせ方、Shift、格子との共存は、ドラッグと同じ。

## 2.5 グループ

ComfyUI のグループは、どちらの表示でも canvas に描かれ、右下の三角でしかリサイズできない。この拡張では、グループもノードと同じ決まりで扱う。グループのためだけの吸い付きは作らない。使う人が、ノードと同じ動きを予想できるようにするため。

- マウスを乗せたときのカーソルは、frontend がカーソルを決める処理（`_updateCursorStyle`）の中で出す。`style.cursor` を直接書くと、frontend の覚えている値と食い違い、角から離れても戻らなくなる。
- グループの枠の中（タイトルと四隅以外）を掴むと、ComfyUI のとおりキャンバスが動く（パン）か、範囲選択になる。グループを動かせるのはタイトルの帯だけ。
- リサイズは四隅から。取っ手の当たり判定は、Nodes 2.0 のノードの角の取っ手に合わせる（2026-11-14 オーナーが決めた）。角ごとに 20 × 20（キャンバスの単位、拡大縮小と一緒に変わる）で、角から外へ 4、内へ 16。内側は、グループの大きさの 1/4 を超えない（小さいグループでもタイトルを掴めるように）。上の二つの角はタイトルの帯にかかる。
  - 外へ 4 はみ出す所は、グループの外（何もない所）でも角の取っ手になる。それより外は、ComfyUI のとおりパンか範囲選択。
- 角に乗せたとき、角に合ったリサイズのカーソルを出す。
- 角のつまみ（Nodes 2.0 のノードの角と同じ、斜めの線 2 本、薄い灰色）は、角に乗せている間と、角でリサイズしている間だけ出す。グループに乗せただけでは出さない（うるさいため。2026-11-14 オーナーが決めた）。
- リサイズは拡張が受け持つ。押した所が角の取っ手（外へはみ出す所を含む）で、ノードの上でなく、ワイヤをつないでいる最中でもなく、reroute・ワイヤの真ん中の印・subgraph の入力と出力の枠の上でもないとき、`app.canvas.pointer` の drag の callback を差し替える。選ぶだけのモード（select only）では受け持たない。選択は変えない（ComfyUI のグループのリサイズと同じ）。左と上の辺を動かすときも、最小の大きさで止める。
- タイトルを掴んで動かすのは、ComfyUI のまま。中のノードも一緒に動き、ほかに選んでいるものも一緒に動き、Ctrl を押していればグループだけ動き、canvas の端で自動スクロールする。吸い付きは、ノードと同じ座標の書き換えで付ける。
- ドラッグとリサイズの吸い付き、補助線、Shift で切ること、格子との共存は、ノードと同じ（1、2）。グループの端も、ノードの吸い付く先になる。
- 拡張が受け持つのは、ドラッグとリサイズの動きだけ。クリック、選択、ダブルクリックでの名前の変更、右クリックは ComfyUI のまま。
- グループの枠の中（タイトルと四隅以外）を押したときは、ComfyUI のまま（パンか範囲選択）。

## 3. 整列メニュー

### 3.1 置き場所

- 標準の浮いたツールバーに、ボタンを**一つだけ**足す。入口は、拡張の `getSelectionToolboxCommands`。ボタンは、選んでいるノードが 2 つ以上のときだけ出す。
- ツールバーのボタンには、マウスを乗せたときの名前を拡張が付ける（frontend は空の名前で描くため）。
- この入口は command の id を返すだけで、frontend はそれをアイコン一つのボタンとして描く（1.58.5 では `ExtensionCommandButton.vue`）。押すと開くメニューは、拡張からは渡せない。
- そこで、ボタンを押したら、拡張が自分でメニューを出す。ボタンは、command の icon に入れた拡張だけの class で見つける。1.58.5 の aria-label は locale の file からしか取られず、空になるので使わない（2026-11-13、両方の表示で確かめた）。
  - frontend の DOM に頼るので、frontend の更新で壊れる恐れがある。それは受け入れる。
  - ボタンが見つからないとき（frontend の描き方が変わったとき）は、メニューを選んでいるノードの上に開く。新しい UI は足さない。command をパレットやキーから呼んだときも、ボタンがあればボタンに、なければ選択の上に開く。選んでいるノードが 2 つ未満なら何もしない。
- 専用のパネルを画面に浮かせる形はとらない。ボタンをいくつもツールバーに並べる形もとらない。
- 浮いたツールバーは、設定 `Comfy.Canvas.SelectionToolbox` で消せる。消しているときは、Run の並び（画面右上）に同じボタンを一つ置く。入口は拡張の `actionBarButtons`（公開 API）。このボタンは Run のバーの外にあるので、Run のバーを浮かせても右上に残る。
  - 選んでいるノードが 2 つ未満のときは、薄くして押せない形にし、マウスを乗せると理由を出す。押しても何も開かない（公開 API では押せなくできないので、拡張が DOM で印を付ける）。
- 浮いたツールバーは、ドラッグの間は消える。メニューもドラッグの間は閉じる。

### 3.2 メニューの形

- **見た目は、コアの Arrange の浮いたメニューに揃える**（2026-11-14 オーナーが決めた）。
  - メニュー: 薄い枠線、背景はテーマの背景色、角丸 8px、ボタンを指す三角（吹き出しの形）。
  - 中のボタン: 薄い色のアイコン、乗せると背景色が付く。開く動きは付けない。
  - ツールバーのボタン: アイコンと下向きの印。アイコンは、コアの揃えのアイコン（lucide の align-*）とも Arrange のアイコン（layout-grid）とも重ならないもの。点線のガイドに 2 本の棒が揃う形を描いた。開いている間は、ボタンに背景色を付ける。
- **ツールバーの上に出す。** ツールバーは選んだノードの上にあるので、メニューが選んだノードを隠さない（コアの Arrange は下に出す）。画面の上端に余裕がないときだけ、ツールバーの下に出す。横はボタンの真ん中に合わせる。Run の並びから開いたときは、そのボタンの下に出す。
- アイコンだけを **2 行 × 5 列**に並べる。文字の見出しと説明文は出さない。名前はマウスを乗せると出す。

|  | 揃え | | | 等間隔 | 大きさ |
|---|---|---|---|---|---|
| 上の行（横の向き） | 左 | 左右の中央 | 右 | 列を横に等間隔 | 幅を揃える |
| 下の行（縦の向き） | 上 | 上下の中央 | 下 | 行を縦に等間隔 | 高さを揃える |

- 行が向き、列が働きを表す。働きの境目には区切り線を入れる。
- 押してもメニューは閉じない（標準の Arrange と同じ）。キャンバスを押すと閉じる。
- 押すとすぐ反映し、元に戻す一回分になる。「適用」「キャンセル」のボタンは置かない。

### 3.3 ボタンの状態

| 状態 | 見せ方 | 押せるか |
|---|---|---|
| 押せる | ふつう | 押せる |
| 押しても何も起きない（等間隔では、列・行が 3 つ未満） | 薄くする | 押せない |
| もうその状態になっている | 色を付ける | 揃え・大きさは押せない。等間隔は押せる（押すと取っ手が出る） |

- 状態は、ノードが動くたびに合わせて変える。ボタンの位置は変えず、消しもしない。
- マウスを乗せると、名前と理由を出す（「列が 3 つ以上いる（今は 2 列）」「もう揃っている」「もう等間隔。押すと取っ手が出る」など）。押せないボタンでも、理由は出す。
- 「もう揃っている」は、値が全部 0.5 以内で一致しているとき。手で置いた「ほぼ揃っている」は、揃っていない扱い。
- 幅を同じにした 2 つを左揃えにすると、中央揃えと右揃えも「もう揃っている」になる。今の状態をそのまま見せるので、それでよい。

### 3.4 それぞれの動き

- 位置と大きさは、見た目の枠（1.1）で数える。
- **揃え**: 選んだもの全体を囲む枠の端（または中央）に合わせる。左揃えなら、一番左のノードの左端に全部を合わせる。もう一方の向きの位置は動かさない。
  - 上揃えは、本体の上端（ヘッダーを除く）で揃える（1.1）。Reroute をノードと上揃えすると、Reroute の箱の上端がノードの本体の上端に来る。
  - 上下の中央揃えは、ヘッダーを含めた箱の中央で揃える（2026-11-14、オーナーに任された）。
- **高さを揃える**は、本体の高さ（ヘッダーを除く）で揃える（2026-11-14 オーナーが決めた）。ヘッダーのあるノードどうしなら、箱の高さで揃えるのと同じ。
- **大きさを揃える**: 一番大きいもの（高さは本体の高さ）に合わせる。高さは、最小より小さくはできないので、一番高いものに合わせる形だけ。Reroute ノードは変えない。
- **等間隔**: 両端（3.5）は動かさず、その間を均等に割る。「決めた値で詰める」形は入れない。
- 固定（pin）したノードは動かさない（ComfyUI のとおり）。揃えの基準やボタンの状態に固定したノードを数えるかは、未決（6）。等間隔では、固定したノードの入った列は動かさない（3.5）。
- 結果は丸めない。等間隔は小数の位置になる（丸めると「もう等間隔」の判定が崩れる）。

### 3.5 等間隔と「同じ列」「同じ行」

ComfyUI には列や行という決まりはないので、拡張が座標から見分ける。等間隔のボタンは二つで、上の段が**列を横に等間隔**、下の段が**行を縦に等間隔**（2026-11-14 オーナーが決めた。列の版と行の版を対にした）。

**同じ列・同じ行**（2026-11-14 オーナーが決めた。前の「範囲が 50% 以上重なれば同じ列」をやめた）

- **同じ列とみなす 2 つ**: 次のどちらかに当たるもの。つながりは連鎖する（A と B、B と C が同じ列なら、A・B・C で一つの列）。
  - 左端・左右の中央・右端のどれかが揃っている（差 20 以内、キャンバスの単位。20 は試し場で置いた値）。
  - 横の範囲（箱で測る）が、もう一方の横の範囲の内側にすっぽり入っている（差 0.5 まで）。幅の広いノードの下に、少し内側へずらして置いた細いノードなど。
- **同じ行とみなす 2 つ**: 縦と横を入れ替えたもの。上端・上下の中央・下端のどれかが 20 以内で揃っているか、縦の範囲が内側に入っている。
  - 上端は本体の上端で測る（「上揃え」3.4 と同じ。上揃えした Reroute とノードは同じ行）。中央と下端は箱で測る。
- 半分重なる、ずれて重なる、だけでは同じ列にしない。等間隔は重なっていても成り立つので、重なりで列を決めると、背の高いノードの階段が一つの列（行）につながったり、動かすたびに列の組み方が変わったりする。
- たまたま端や中央が 20 以内に来た二つや、幅の広いノード一つの下に並べた細いノード二つも、同じ列として一緒に動く。点線の囲み（3.6）で見える。
- 行でも同じなので、背の高いノードの横に小さなノードを縦に積むと、全部が一つの行になる（小さなノードは背の高いノードの縦の範囲に入るため）。「行を縦に等間隔」は「今は 1 行」で押せない。積んだ小さなノードだけを選べば、それらの行を等間隔にできる。

**等間隔の置き方**

- **列を横に等間隔**: 同じ列をひとかたまりにして、列ごと横に動かす。列の中の並びはそのまま。ノードは横にしか動かないので、水平にしたワイヤは外れない。
- **行を縦に等間隔**: 同じ行をひとかたまりにして、行ごと縦に動かす。ほかの行とつながるワイヤの水平は外れることがある。
- **列の始まり**: 列のノードのうち、いちばん前の左端（行なら、いちばん上の本体の上端）。列の順、重なりきったときに止まる所、縮めきって揃う所は、この始まりで決める。だから、縮めきると Reroute とノードは「上揃え」（3.4）と同じ形で揃う。
- **順と両端**: 列の順は、列の始まりの順。いちばん初めの列の始まりと、順でいちばん後の列の終わり（右端・下端）は動かさない。途中の列がそれより外へはみ出していれば、それは動く。
- **すき間**: 前の列の終わり（箱の右端・下端）から次の列の箱の始まり（左端・上端）まで。重なっていればマイナス。両端の間で、すき間を全部等しくする。
- **重なっていてもよい**（2026-11-14 オーナーが決めた）: すき間はマイナスのまま等しくする（どの隣どうしも同じだけ重なる）。重なり、ぶつかり、固定で断ることはしない。断るのは、列（行）が 3 つ未満のときだけ。
- **重なりきった列は止まる**（2026-11-14 オーナーが決めた）: マイナスのすき間が、前の列の長さより大きくなると、次の列が前の列の始まりを追い越してしまう。そうはせず、次の列は前の列と同じ始まりで止まる（その二つは始まりが揃う）。ほかの列どうしは等しいすき間のまま。だから、背の高いノードの横に背の低いノードを並べたときなどは、止まった所だけすき間が等しくならない。順は入れ替わらない。
- **固定**（pin）したノードは動かさない（3.4）。固定したノードの入った列は、列ごと動かさない（ほかのノードだけが動いて列がほどけないように）。ほかの列は、固定した列がないものとして置く。
- **「もう等間隔」**は、押しても何も動かないこと（すべての位置の差が 0.5 以内）。だから、一度押せば必ず「もう等間隔」になり、二度押しても何も起きない。
- **取っ手を出している間**は、ボタンの状態と取っ手と囲みは、押したときに見分けた列とその順のまま扱う（動かした結果、端がたまたま揃って列がつながったり、始まりが同じになったりしても、見分け直さない）。選択を変えたとき、元に戻したとき、取っ手以外で選んだノードを動かしたときは、取っ手を消して見分け直す。そのとき、縮めきって揃った並びは一つの列（行）になり、「列が 3 つ以上いる」で押せなくなる。それは「もう揃っている」ということなので、そのままにする。

### 3.6 等間隔の取っ手

- 等間隔を押した直後だけ、**すき間ごとに取っ手を一つ出す**（等しいのはすき間なので、操作もすき間に置く。2026-11-14 オーナーと決めた）。取っ手は強調の色の細い棒（横の等間隔なら 6 × 24、縦なら 24 × 6、画面の px）で、縁は付けない。
- **取っ手の位置**（すき間の向き。縦の等間隔なら縦の位置）: 次の列の始まりから、すき間の半分だけ前。ただし、すき間の半分が画面で 10 px より小さいとき（すき間が小さい、0、マイナスのとき）は、次の列の始まりから画面で 10 px 前。すき間が 0 をまたいでも、取っ手は続けて動く。
- **取っ手の位置**（もう一方の向き）: すき間ごとに、押したときの並びで決め、取っ手を出している間は変えない（引いても、離しても、もう一度押しても）。UI があちこちへ動かないため（2026-11-14 オーナーが決めた）。選び直すと、そのときの並びで決め直す。
  - すき間がプラスなら、選んだもの全体の真ん中。
  - 0 以下なら、すき間の真ん中は重なった二つのノードの上になるので、次の列の始まりのノード（始まりがいちばん前のもの。同じなら、もう一方の向きでいちばん前のもの）の真ん中（とても長いノードでは、端から 300 の所）。オーナーが図で示した位置（下のノードの上、ノードの真ん中）。
  - ほかのノードが重なっていて、取っ手がその上に来ることはある（取っ手は前に出るので掴める）。
- **数字**: 取っ手ごとに、そのすき間の実際の大きさを数字で出す。同じ数字が並ぶことで「等しい」と読める。重なりきって止まった所は、その実際のすき間（前の列の長さのマイナス）を出すので、ほかと違う数字になる。マイナスなら「-40」。小数は四捨五入し、「-0」は「0」と出す。
  - 置き場所は取っ手の横（横の等間隔なら取っ手の上、縦なら右）。すき間がプラスで、数字がすき間に収まらないときは出さない。0 以下のときは必ず出し、ノードの上でも読めるよう、数字の下に背景の色の下地を敷く。
  - 取っ手と数字が同じ所に重なったら（縮めきったときなど）、後ろのすき間のものだけを出し、その取っ手を前にする（掴めるのはそれ）。
- **引くと**: どの取っ手を引いても、全部のすき間が同じだけ伸び縮みする。**掴んだ取っ手から遠い側の端が動かない**（2026-11-14 オーナーと決めた）。右半分（下半分）の取っ手なら左端（上端）、左半分なら右端が動かず、取っ手はマウスの下に付いてくる。真ん中の取っ手（すき間が奇数のとき）は、真ん中を動かさずに両側へ広がる（引いた距離だけ両端が外へ動く）。
  - すき間はプラスからマイナスまで続けて変えられる（2026-11-14 オーナーが決めた。前は 0 で止めていた）。重なりきった列は止まる（3.5）。
  - 重なりきった列が止まると、その先は取っ手を引いても取っ手自体は動かなくなることがある。そこからは、マウスを動かした分だけすき間が縮み続け、取っ手はその場に残る。だから、どの取っ手からでも縮めきれる。
  - 縮めきると、全部の列の始まりが揃う（大きさに関係なく、左揃え・上揃え）。そこより先へは縮まない。
  - 真ん中の取っ手は、引き始めたときの「いちばん初めの列の始まり」と「いちばん後の列の終わり」の真ん中を動かさず、全体の長さを引いた距離の 2 倍だけ伸び縮みさせる。縮めきると、全部の列の始まりが、その真ん中から後の列の長さの半分だけ前の所で揃う。
  - 画面の 10 px は、引き始めたときの拡大率でキャンバスの長さに直す。
- **列や行の囲み**: 取っ手を出している間は、ノードが 2 つ以上の列（行）を細い点線で囲む（線は箱の端ちょうど）。
- 選択が変わると取っ手は消える。元に戻したときも消える。もう等間隔のものは、色の付いた等間隔のボタンを押せば、取っ手がまた出る。
- 取っ手を引く一回が、元に戻す一回分。

## 4. 設定

ComfyUI の設定画面に、拡張の `settings` で足す。好みが割れるものだけを出す。

1. ドラッグ中に吸い付く（on/off）。まとめて切るため。
2. 何に吸い付くか: 「ワイヤの水平」と「ほかのノードの端（ぴったり付けるを含む）」を別々に on/off。
3. 吸い付く強さ: 入る距離を一つのスライダーで変える。外れる距離は、入る距離から決める（試し場の 8 と 14 の比）。マウスやペンタブ、画面の解像度で、ちょうどよい値が変わるため。
4. 色: 「テーマの強調の色を使う」（初期は on）と、off のときの「色」。補助線、取っ手、寸法線、列や行の囲み、メニューの「もうその状態」は、全部この一色で描き、違いは形（実線、点線、取っ手）で出す。初期はテーマの強調の色（`--primary`、Run ボタンの色）。好みが分かれるので、人ごとに選べるようにした（2026-11-14 オーナーが決めた）。

相手の範囲、知らせ方、同じ列とみなす差などは設定に出さず、この仕様書で決める。

## 5. 入れないもの

- ドラッグ中に、Figma 式の等間隔（2 つの間の真ん中、並びを延ばす位置）に吸い付くこと。欲しい等間隔の形と違った。
- 引き寄せる吸い付き。
- 速く動かしている間は吸い付かない仕掛け。
- 一方向だけに動かすキー（1.5）。
- 選んだノードのワイヤを一回で水平にする命令。頼まれたものではなかった。
- 決めた値で詰める等間隔。
- 標準の Arrange の流用。Arrange は、選んだノードを一番左上のノードから一列（または格子）に詰め直す機能（間隔は 0〜48 のスライダー）で、ワイヤも選んでいないノードも見ないため、揃える用途には合わない（ComfyUI-dev の frontend 1.58.5 で押して確かめた）。
- ComfyUI の右クリックにある Align Selected To / Distribute Nodes の置き換え。そのまま残す。こちらは `pos` で数え、列を見ない。この拡張のメニューは見た目の枠で数え、列を見る。
- 専用の浮いたパネル。
- グループの枠を、大きさを変えずに動かして、中のノードを枠の真ん中に置く命令。どう動くかが使う人に伝わりにくい。ComfyUI の Fit Group To Nodes は枠の大きさも変えるので、これとは別の働き（2026-11-14）。

## 6. 未決

オーナーが決めること。実装では、決まるまで次の形にしておく（括弧の中）。

- ドラッグの後に、閉じたメニューを開き直すか。（開き直さない）
- メニューのボタンを押すと、選んだものの枠が変わり、ツールバーとメニューが動く。次に押すボタンがずれる。メニューの位置を、開いた所に留めるか。（ツールバーについていく）
- 揃え・等間隔で、固定（pin）したノードを基準にするか、数えないか。（動かさず、基準と状態の判定には数える）
- 設定 1（ドラッグ中に吸い付く）を off にしたとき、Shift での格子と、グループの四隅のリサイズを ComfyUI に戻すか。（Shift の格子は ComfyUI に戻す。グループの四隅のリサイズは残す）
- 自分の入っているグループの枠や、グループの中のノードを、吸い付く先にするか。（する）
- 「ぴったり付ける」の形にたまたまなっているとき（吸い付いていないが、上端が相手の下端と一致）、補助線を出すか。（出す）
- ワイヤの上の reroute を掴んだとき、吸い付かせるか。（吸い付かせない。subgraph の入力・出力の枠は 2026-11-16 に決まった、1.1）
- 整列メニューで、選択にグループやワイヤの上の reroute が入っているとき、それも揃えるか。（ノードだけを揃え、ほかは動かさない）
- 折りたたんだノードを、大きさ揃えでどう扱うか。見えている大きさは変えられないので、選べるのは「開いたときの大きさを変えるか」だけ。（変えない）

## 7. 実装で確かめること

試しで確かめた形（`docs/review/2026-11-14-probes.md`）で作る。そのうえで、次を両方の表示で確かめる。

- 拡張が頼る frontend の内部（`LGraphCanvas.prototype._processPrimaryButton`、`LGraph.prototype.getSnapToGridSize` / `snapToGrid`、`app.canvas.pointer` の callback、event の座標と `shiftKey`）が見つからないときは、その働きを切り、ほかの働きは続ける。
- 折りたたんだノード、ワイヤの上の reroute、subgraph の中での動き。入力・出力の枠とのワイヤは、2026-11-16 に両方の表示で確かめた（ノードを動かすとき、枠を動かすとき、Alt で枠を動かすとき、枠とノードをいっしょに選んでノードを掴むとき。枠の行を並べ直す拡張を入れた状態を含む。枠のドラッグは一回の Ctrl+Z で戻る）。枠と reroute を両方通るワイヤ、枠を掴んでいる間の Shift・格子・「常に格子に吸い付く」、枠の見た目を変える拡張の帯やラベルを押したときは、まだ見ていない。
- 元に戻したあと（graph が読み直される）に、メニューや取っ手が古いノードを掴んだままにならないか。
- ツールバーが動いたり消えたりしたときに、メニューがついていくか。
- Run の並びのボタンは、設定を読む getter で出し分ければ、読み直しなしで出たり消えたりする（frontend の `cloudFeedbackTopbarButton.ts` と同じ形）。Run のバーを浮かせたときに右上に残るかは、まだ見ていない。
- リサイズ中の「常に格子に吸い付く」で、吸い付いた辺を直す作り方（1.6）。
- 元に戻すを拡張がまとめる作り方（根っこの決まり）を、旧来のリサイズ、Nodes 2.0 のドラッグとリサイズで。修飾キーを途中で離したときも一回分になるか。
- 座標の書き換えを、縮小（0.5 など）、パンした後、ゆっくりした動き、複数の選択、グループのタイトルドラッグで。
- 同じ働きの拡張（easykit-node-align、Pixaroma の Align など）と一緒に入っているときの動き。確かめる環境では外しておく。

## 試し場との違い

試し場（`docs/playground.html`）は使い心地を決めるための模型で、次の点がこの仕様書と違う。

- 「ぴったり付ける」（1.1）がない。
- 吸い付きを切るのが Ctrl で、Shift が一方向だけに動かすキー（1.5 で、Shift で切る形に変え、一方向のキーはなくした）。途中で一方向のキーを押すと、始めの行・列に引き戻される。
- リサイズは右下の角だけで、高さが吸い付かず、補助線は右端だけに出る。リサイズを始めると、ほかの選択が外れる（2）。
- グループがない（2.5）。
- 格子に合わせるのがドラッグの途中で、離したときではない（1.6）。
- 相手の範囲の初期値が「画面に見えているノード」で、ほかの選択肢（全部、近く、つながっているもの）も切り替えられる。
- 選んだノードのワイヤを一回で水平にする Q キーがある（5 で外した）。
- 設定の欄に、仕様では出さない項目（知らせ方、速さ、候補の優先など）が並んでいる。
- ツールバーとメニューは画面の中に収まるよう位置を直すが、本物のツールバーは直さない。
- ノードの大きさやスロットの位置は、ComfyUI に似せた作り物。
